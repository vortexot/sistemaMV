# Rotação de credenciais de produção

| NOME DA CREDENCIAL | SERVIÇO | COMO GERAR NOVA | ONDE CONFIGURAR | O QUE REINICIAR | COMO VALIDAR | QUANDO REVOGAR A ANTIGA |
|---|---|---|---|---|---|---|
| `JWT_SECRET` | API FastAPI | Gerar pelo secrets manager com CSPRNG e pelo menos 32 bytes | Secret do serviço backend | Todas as instâncias da API | Startup passa; login/refresh novos funcionam; tokens anteriores retornam 401 | Depois que todas as instâncias usam a nova versão; a troca encerra sessões existentes |
| `MFA_ENCRYPTION_KEY` | MFA TOTP | `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` em terminal seguro | Definir a nova em `MFA_ENCRYPTION_KEY` e a antiga temporariamente em `MFA_ENCRYPTION_KEY_PREVIOUS` | API e, depois, o job controlado de migração | Executar `rotate_mfa_secrets.py` sem `--apply`, fazer backup, executar com `--apply` e repetir dry-run até `previous=0 unreadable=0`; testar login de contingência | Remover `MFA_ENCRYPTION_KEY_PREVIOUS` somente após `previous=0`, restore disponível e login MFA validado |
| Credencial de `MONGO_URL` | MongoDB | Criar usuário/segredo novo com privilégio mínimo no serviço Mongo | Secret `MONGO_URL` do backend | API e tarefas que acessam o banco | Health/startup, índices, leitura e transação sintética em staging | Depois que todos os consumidores usam a conta nova e logs não mostram falha; então revogar a conta antiga |
| `PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET` | PayPal | Criar credencial de aplicação no painel oficial; Sandbox para staging | Secrets do backend | API | Com `PAYPAL_MODE=sandbox`, executar o roteiro `PAYPAL_SANDBOX_TEST.md` | Depois que criação, captura e conciliação funcionarem com a nova credencial; Live somente após pentest e autorização |
| `RESET_WEBHOOK_TOKEN` | Entrega de recuperação de senha | Emitir token aleatório no serviço de entrega | Secret no backend e credencial correspondente no serviço de entrega | API e serviço de entrega | Solicitação sintética chega ao destino permitido; destino inválido continua 503; token nunca aparece em log | Depois que ambos os lados usam o token novo e a entrega foi confirmada |
